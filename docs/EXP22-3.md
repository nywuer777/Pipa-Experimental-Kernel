## Risco e autorização

`fastboot boot` **inicia uma imagem carregada na RAM**, é diferente de `fastboot flash` que grava uma partição, mas não garante sucesso do Linux/Android nem ausência absoluta de alterações indiretas/metadados. Falha do EXP06 pode travar na splash, perder ADB, exigir recuperação física Power + Volume Down, reconexão do Fastboot e reinício pelo boot B persistente. O método de acesso ao bootloader sob kernel experimental travado ainda não foi testado. Fazer backup de dados importantes do usuário antes da tentativa; backups de boot não cobrem userdata.

**Aguardar nova autorização expressa para uma única tentativa temporária do EXP06.** A autorização anterior não cobre esta operação. NÃO autoriza flash, erase, mudança de slot, alteração vbmeta, "fastboot --set-active", root/KernelSU extra ou TWRP.

## Execução manual DEPOIS de autorização específica (não executar antes)

### Pré-checagens no Windows com Android normal

```powershell
$adb="C:\platform-tools\adb.exe"
$fb="C:\platform-tools\fastboot.exe"
$experimental="$env:USERPROFILE\Downloads\EXP19-output\EXP19-EXP06-NOT-FOR-FLASH.candidate.bin"
$original="C:\platform-tools\pipa_backup\boot_b.img"

if ((Get-Item -LiteralPath $experimental -ErrorAction Stop).Length -ne 32206848 -or
 (Get-FileHash -LiteralPath $experimental -Algorithm SHA256).Hash -ne "30065a39be707d836594da574be11b08c0228018ca91a681e1b122e6f0e6f60c") {
 throw "EXP22.3: SHA/tamanho EXP06 invalido; ABORTAR"
}
if ((Get-Item -LiteralPath $original -ErrorAction Stop).Length -ne 201326592 -or
 (Get-FileHash -LiteralPath $original -Algorithm SHA256).Hash -ne "31f57cded5fa4b37426b4387b58c1c7330703a1c1a8a5aa584b348fcbb78c2f4") {
 throw "EXP22.3: SHA/tamanho backup original invalido; ABORTAR"
}

$device=(& $adb shell getprop ro.product.device | Out-String).Trim()
if ($LASTEXITCODE -ne 0 -or $device -ne "pipa") { throw "EXP22.3: dispositivo inesperado" }
$slot=(& $adb shell getprop ro.boot.slot_suffix | Out-String).Trim()
if ($LASTEXITCODE -ne 0 -or $slot -ne "_b") { throw "EXP22.3: slot inesperado" }
Write-Output "EXP22.3 PREBOOT_LOCAL=PASS"
```

O caminho de prova primária é o hash fixado do candidato enviado ao bootloader, confirmação `Booting OKAY` e Android iniciado; idealmente adicionar evidência explícita do parâmetro schedutil de `1500us` em uma consulta separada, apenas se realmente exposto e verificável no kernel em execução. Nunca atribuir estabilidade/FPS/benefício ao EXP06 somente pela versão do kernel.

### Interrupção e contingência

1. Se `fastboot boot` devolver FAILED, **não insistir** e **não tentar flash**; se permanecer no bootloader, `fastboot reboot` retorna à imagem persistente, depois confirmar ADB.
2. Se não iniciar Android ou ADB, observar tela e conexão Fastboot; recuperar bootloader fisicamente (Power + Volume Down, quando necessário), sem modificar slots. Acesso a Fastboot durante boot travado não foi homologado; um risco material.
3. Em Fastboot após falha, confirmar novamente `product=pipa` e `slot=b`. `fastboot reboot` tenta iniciar o original persistente, sem gravar. Não executar comandos de flash como reação automática a erro.
4. Se Android com EXP06 iniciar, observar inicialização e conectividade; realizar, em etapa separada, reboot normal e verificar Android persistente original, bem como opcionalmente SHA256 raw read-only de `boot_b` para demonstrar bytes preservados.
5. Falha ou erro não constitui autorização para outras operações.

## Critérios de decisão

- `EXP22.3_FASTBOOT_SEND_AND_BOOT=PASS/FAIL/UNKNOWN` por console Windows.

- `EXP22.3_RETURN_TO_PERSISTENT_ORIGINAL=PASS/FAIL/UNKNOWN` só após reinicialização normal comprovada.
- `FLASH_READY=false` independentemente do resultado temporal; a operação não autoriza gravar kernel em `boot_b`.

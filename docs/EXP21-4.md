# EXP21.4 — Diferenciar versão ativa Android e fingerprint OEM, sem alterar slot

**Data:** 2026-10-18 | **Entrada:** EXP21.3 aprovada no Xiaomi Pad 6 (`pipa`), ADB habilitado, slot `_b`.

## Motivo

O Android reportou `ro.build.fingerprint=Xiaomi/pipa_pad_cn/pipa:14/UKQ1.240624.001/OS2.0.19.0.UMZCNXM:user/release-keys`, que descreve uma compilação OEM identificada como Android 14. Entretanto, um sistema com personalizações, base de vendor reaproveitada ou propriedades sobrepostas pode expor um fingerprint OEM diferente da versão de framework em execução. Não inferir versão real do Android a partir desse único valor.

Fonte principal AOSP: https://android.googlesource.com/platform/frameworks/base/+/master/core/java/android/os/Build.java . O framework diferencia `ro.build.fingerprint`, `ro.system.build.fingerprint`, `ro.vendor.build.fingerprint` e outras propriedades de build por partição.

## Consultas somente leitura

Windows PowerShell:

```powershell
$adb = "C:\platform-tools\adb.exe"
& $adb devices -l
& $adb shell getprop ro.product.device
& $adb shell getprop ro.boot.slot_suffix

$props = @(
  "ro.build.version.release",
  "ro.build.version.sdk",
  "ro.system.build.version.release",
  "ro.system.build.version.sdk",
  "ro.product.build.version.release",
  "ro.vendor.build.version.release",
  "ro.build.display.id",
  "ro.build.fingerprint",
  "ro.system.build.fingerprint",
  "ro.vendor.build.fingerprint",
  "ro.crdroid.version"
)
foreach ($prop in $props) {
  $value = (& $adb shell getprop $prop | Out-String).Trim()
  Write-Output "$prop=$value"
}
```

Os comandos não tentam `su`, não acessam o conteúdo das partições, não escrevem nada, não fazem reboot e não mudam o slot. Propriedades inexistentes podem retornar uma string vazia; nesse caso registrar `UNKNOWN`, sem inventar valores.

## Interpretação e próximos bloqueios

- Versão `ro.build.version.release` e API `ro.build.version.sdk` ajudam a identificar o framework Android ativo, mas são propriedades e podem ser alteradas pela ROM.
- `ro.vendor.*` descreve o lado vendor e pode diferir do sistema devido a suporte Treble, não é automaticamente erro.
- `ro.crdroid.version` é somente uma pista opcional de ROM.
- Dados do sistema atualmente inicializado dizem respeito ao slot `_b`, não são prova do conteúdo atual do slot `_a`.
- O próximo portão de segurança para confiar no slot `_a` requer método somente leitura, autorizado, de inspeção do **conteúdo** das partições A, com hashes auditáveis e avaliação de compatibilidade de firmware/ROM. Não ativar A como experimento.
- Os backups de `_b` com hashes aprovados e o candidato offline EXP06 continuam intocados.

**Estado:** `EXP21.3=PASS_REAL`, `EXP21.4=DATA_PENDING`, `FLASH_READY=false`. Nenhum flash, `fastboot boot`, troca de slot, ou alteração de boot control autorizados.

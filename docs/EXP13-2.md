# EXP13.2 — Correspondência dos hashes AVB com os backups originais (sem flash)

## Evidência EXP13.1

Homologação real no computador do usuário:

```text
EXP13.1 REAL AVB PARTITION NAME AUDIT: PASS
SOURCE=vbmeta_b.img verified_sha256=86d703c2ea2f73a55aa86374329bd89ffd975c0e95e33645a156cfdc343889ff
DESCRIPTORS total=15 chain=1 hash=3 hashtree=2 other=9
VBMETA flags=3 signature_verified=False trusted_key_verified=False hardware_rollback_checked=False
PARTITION kind=chain name=vbmeta_system flags=0 rollback_location=1
PARTITION kind=hash name=boot flags=0 image_bytes=31920128 algorithm=sha256
PARTITION kind=hash name=dtbo flags=0 image_bytes=692224 algorithm=sha256
PARTITION kind=hash name=vendor_boot flags=0 image_bytes=20697088 algorithm=sha256
PARTITION kind=hashtree name=odm flags=0 image_bytes=1609728 algorithm=sha256
PARTITION kind=hashtree name=vendor flags=0 image_bytes=964849664 algorithm=sha256
NO FILE MODIFIED. NO BOOT IMAGE CREATED. FLASH_READY=false
```

O Android informa **`green`/`locked`/`veritymode=enforcing`**. A presença de `flags=3` no cabeçalho AVB original não substitui a validação da cadeia de confiança, nem constitui autorização para gravar a imagem.

## Análise dos comprimentos declarados

A partir dos offsets estruturalmente homologados na EXP12:

| Partição | AVB hash image_size | Último byte significativo conhecido (limite exclusivo) | Comparação |
| --- | ---: | ---: | --- |
| `boot` | 31.920.128 | 32.204.801 (fim da ramdisk genérica) | hash declara 284.673 bytes a menos |
| `vendor_boot` | 20.697.088 | 20.878.874 (fim da DTB) | hash declara 181.786 bytes a menos |
| `dtbo` | 692.224 | 688.455 (fim da tabela DTBO) | hash abrange 3.769 bytes adicionais de padding |

Os campos `AvbHashDescriptor.image_size` são os **comprimentos de imagem de entrada no hash**, não o tamanho total da partição. Diferenças de tamanho **não demonstram, sozinhas, alteração, corrupção ou incompatibilidade**. Entretanto, elas exigem verificação explícita para determinar se o vbmeta do backup pertence ao mesmo conjunto de imagens de boot.

## Implementação EXP13.2

Ferramenta: [`tools/exp13-2-avb-hash-crosscheck.ps1`](https://github.com/nywuer777/Pipa-Experimental-Kernel/blob/main/tools/exp13-2-avb-hash-crosscheck.ps1).

- Lê apenas os backups privados locais `vbmeta_b.img`, `boot_b.img`, `dtbo_b.img`, `vendor_boot_b.img` e valida **primeiro** os quatro SHA-256 originais completos da EXP12/13.
- Percorre os descritores AVB e extrai os 3 hash descriptors de 132 bytes (fixed header), com bounds checks e algoritmo SHA-256.
- Recalcula o valor `SHA256(salt || primeiros image_size bytes da partição)`, usando streaming de até 1 MiB por bloco.
- Compara o digest recalculado com o digest armazenado sem imprimi-los. Exibe somente `MATCH` ou `MISMATCH`, o limite de `image_size`, `known_used_end` e um booleano se o hash cobre inteiramente as estruturas homologadas.
- Não mostra salts, digests, valores de propriedades, assinaturas, chaves ou conteúdo bruto.
- Rejeita nomes de partição inesperados, buffers fora dos limites, digest persistente sem bytes e backup com SHA-256 alterado.
- Não usa ADB nem altera partições ou imagens.

### Como executar no Windows

Baixe o `exp13-2-avb-hash-crosscheck.ps1` disponibilizado no chat, salve-o em Downloads e execute:

```powershell
Copy-Item "$env:USERPROFILE\Downloads\exp13-2-avb-hash-crosscheck.ps1" "C:\platform-tools\exp13-2-run.ps1" -Force

powershell -NoProfile -ExecutionPolicy Bypass -File "C:\platform-tools\exp13-2-run.ps1" -BackupDir "C:\platform-tools\pipa_backup"
```

A saída indicará `RESULT=ALL_THREE_MATCH` ou `RESULT=ONE_OR_MORE_MISMATCH`, mas **nenhum desses resultados, isoladamente, libera flash**. Um `MISMATCH` pode significar que o descritor refere outra compilação, um estágio ignorado da cadeia ou uma incompatibilidade; é necessária análise adicional antes de atribuir causa.

## Portão

**`FLASH_READY=false`**. A assinatura do `vbmeta_b.img`, a chave confiável, os índices de rollback em hardware e o comportamento real do bootloader continuam sem verificação. O hash de descritor **não substitui** validação criptográfica da assinatura AVB. Não desbloquear bootloader nem fazer flash/fastboot boot.

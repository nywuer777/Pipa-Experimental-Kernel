## Changes

- New `shaders/pipa_scene_3d.comp`, same (RGBA8 storage image, 16x16, 16-byte push constants) scene renderer API as V2.
- Analytical perspective ray/plane and three ray/sphere intersections, depth ordering, objects moving at independent depths, animated camera parallax, checkerboard ground in world-space and stationary HUD crosshair. This tests motion boundaries/disocclusion beyond periodic 2D translation.
- This is **3D scene generated by Vulkan Compute** and not a rasterization pipeline, depth-buffer integration, Unity game, driver interception or universal framegen.
- Dual default-visible `3D 10s HOLD 72→144` and `3D 10s FrameGen 72→144` profiles (1440 presentation attempts, target 144Hz).
- Original diagnostics remain behind `Mostrar / ocultar testes anteriores` to increase available scene space.
- Retained SYNC WSI and optional Motion FAST radius3, baseline radius4, GPU Motion/Warp split and clipboard export.
- Build code 311, NDK r27c, Android arm64. Kernel EXP27, KGSL, Turnip and SurfaceFlinger unchanged.

## Hardware validation and rollback

1. SYNC on, FAST off (radius4 baseline). Run 3D HOLD 10s then 3D FrameGen 10s. Copy each full report.
2. Visually check sphere edge boundaries, changing occlusions, floor perspective convergence, HUD ghosting, and whether any bottom stripe returns.
3. If stable, repeat 3D FG with Motion FAST on (radius3) and compare Motion and Warp p95, total generated p95, WSI adjacent interval long gaps, and visual artifacts.
4. Start with 10s; monitor thermal response. A missed deadline counter indicates CPU wake scheduling, not physical dropped frames.
5. Investigate depth-aware motion masks, foreground/background de-occlusion and HUD preservation in future releases; shader currently emits only RGBA color, no depth or motion vectors.
6. Debug release is reversible by uninstalling APK if appropriate (preserve app data). Never flash EXP27 or alter drivers for this test.
